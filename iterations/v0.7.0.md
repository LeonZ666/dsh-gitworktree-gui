## Requirements

界面布局结构要求（三层结构）

插件界面改为分为上中下三部分：

增加顶部【当前 Worktree 部分提取单独放到顶部】：

- 展示当前 Worktree 路径。
- 展示当前分支名（如果是 detached HEAD 则显示 `detached @ <commit_hash>`）。
- 展示 Ahead/Behind 状态（如 ↑2 ↓0）以及工作区状态（clean / dirty / conflict，dirty 需标橙色）。
- 展示全局统计计数：`本地分支 X · 远程分支 Y · Worktree Z`。

中部保留当前顶部的可视化功能。

底部保留剩下部分，新增：用户点击图上的节点（Commit、分支或 Worktree）时，在底部或右侧显示详细信息（路径、HEAD commit、上游分支、dirty 文件数等）。

## Goals / non-goals

**Goal**：把面板重排为「顶部当前 Worktree 信息条 → 中部拓扑图 → 底部列表 + 节点详情」三层；顶部条补全分支/detached、ahead-behind、clean-dirty-conflict、全局计数；点击 Commit / 分支 / Worktree 节点在底部详情区显示该对象的详细信息；CHANGES / FILES 的文件行点击后在侧边栏新开文件预览 tab。

**Non-goals**：

- 不改动 DSH / Codex / Claude 三端的数据契约（`getState` 结构保持兼容，只增字段）。
- 不新增写操作（不 checkout / fetch / prune），面板仍为只读。
- 不做详情面板的持久化或跨会话记忆；选中状态只存在于当前页面生命周期。
- 不做移动端/窄屏专门布局，沿用侧栏宽度。
- 不新增文件读取路由：文件预览复用内置 document preview 与 workspace-files 读取。

## Decisions

- **三层结构**：`.gw-wtbar`（顶部、固定不滚动）→ `.gw-body` 的 `.gw-top`（拓扑，保留原有可拖拽分割）→ `.gw-bottom`（详情 + 其他工作树 / CHANGES / FILES）。顶部条不再放 "正在查看 · path"，路径直接作为当前 Worktree 的主行。
- **当前工作树只出现在顶部**：底部 WORKTREES 列表过滤掉正在查看的树，只列出其余工作树；单一工作树的仓库不再显示空的 WORKTREES 区。顶部条承接原行信息：`主树` 徽标与 `已修改/未跟踪/冲突` 明细，计数行仍在最下方。
- **顶部条数据**：当前树取 `worktrees.isSelected`；分支 `detached @ <short>`；状态按 `conflicted > 0 → conflict`、`dirtyTotal > 0 → dirty`、否则 `clean`，dirty 用 warn 橙；ahead/behind 取自 `git status --porcelain=v2 --branch`；计数为 `branches.length` + 新增 `remoteBranchCount` + `worktrees.length`。
- **详情面板放在底部而不是右侧**：侧栏宽度有限，右侧再分割会压扁拓扑；详情作为 `.gw-bottom` 的第一块，原有的 WORKTREES / CHANGES / FILES 全部保留在下面，符合「底部保留剩下部分」。
- **点击语义**：Commit 节点 → 提交详情（原有）；分支线段/引用 → 选中轨道并显示分支详情；图的引用顶点与列表里的 Worktree 行 → 切到该工作树并同时显示其详情（保留原来"点顶点切换"的行为）；详情里的「查看提交」直接读该 HEAD 的提交详情。
- **文件点击复用侧边栏预览**：不新增文件读取路由，CHANGES / FILES 的文件行调用 `ctx.sidebarRight.openResource()`，地址为 `dsh-resource://file/session/<sessionId>/<绝对路径>`（按段编码，保留前导 `/`），由内置 document preview 按文件开新 tab；目录类 entry（`dir/`）与没有资源注册表的宿主保持不可点击。
- **数据契约只增不改**：`parseStatus` 增加 `upstream`；分支列表增加 `upstream/ahead/behind`；`collectState` 增加 `remoteBranchCount`，旧消费者忽略新字段即可。
- 选中状态 `{kind, sha|name|path, scope}` 不持久化；切换会话或返回会话工作区时清空。
- **README 收束到 DSH**：只保留 DSH 的安装与使用；Codex / Claude 的平台细节、能力表、配置与 FAQ 移除，压成文末一句「也能在 Codex 和 Claude 上安装」。新增 `assets/readme/panel-map.svg` 说明三层结构，hero 版本改为 v0.7.0，提交详情截图裁到详情区域；安装章节补「从 npm 安装」（`dsh plugin --profile <profile> add dsh-gitworktree-gui`，桌面 profile 走插件页 / `plugin_manager`）。

## Leftovers

- `assets/readme/panel.jpg`、`rules.svg` 已不再被 README 引用（panel-map 为结构示意）；如要真实反映三层布局，需要在实际 DSH 侧栏重新截图。`commit-detail.jpg` 是从 v0.6.0 截图裁出的详情区域，仅证明提交详情内容，不含新顶部条。
- Claude 原生 Pane（`hooks/register.tsx`）仍是独立文本渲染，不含顶部信息条与点击详情；本次按 non-goal 未改。
- Codex 适配页复用同一 Panel，但没有 DSH 的 `sidebarRight` 资源注册表，文件行保持不可点击；如需在 Codex 内预览，需要另做服务端文件页。
- 详情目前只在底部；若后续侧栏更宽，可评估右侧分栏。
- 尚未在运行中的 DSH 页面人工验收（包括点击 CHANGES/FILES 是否按预期打开预览 tab）：`client.js` 改动刷新页面即可，`lib/core.js` 改动需重启 DSH 才生效。
- 文件预览依赖内置 document preview 与 workspace-files；该插件被禁用时文件行仍显示可点击，但只会记录 console warn，不会打开 tab。
